# NTFSDriver 开发与验收计划

计划日期：2026-10-12。需求依据：[PRD v1.0](PRD.md)。目标环境为 Apple Silicon / macOS 27.0.1。

先建立安全只读引擎与可编译适配，再验证标准本地卷及可控的 NTFS 探测和挂载流程。每个阶段完成其安全与集成验收后，才开放下一阶段的能力。维护者不办理付费开发者账号，自己的 FSKit 授权与发行签名当前缺失；后续系统集成须评估已有签名组件或实际开源发布方，详见 [签名与系统集成限制](SIGNING.md)。

## M1 已交付范围

M1 的诊断输入为从 NTFS 分区起始扇区开始的原始普通文件镜像。工具以只读文件描述符读取有界头部，拒绝设备节点、目录、FIFO 和末级符号链接。完整磁盘的分区表、DMG 容器和真实磁盘访问不属于本批范围。

检查 OEM 标识、引导扇区结束标记、保留字段、扇区与簇大小、卷长度、MFT 与镜像 MFT 位置、记录大小编码及整数溢出。这里只能确认引导结构，不能确认完整 NTFS 文件系统健康。诊断始终报告写入被拒绝，Dirty Flag、休眠状态及元数据一致性仍为未知。

FSKit 适配器只探测块设备头部。它最多返回“已识别”，不返回“可用”；加载、检查、格式化全部拒绝。本批不安装或注册扩展，因此不会改变当前磁盘的挂载流程。

## 引擎接入门禁

M2 已固定 NTFS-3G 2026.9.28 提交并引入未修改的引擎源码，项目代码采用 GPL-3.0-or-later；接入结论见 [引擎审查](ENGINE_AUDIT.md)，来源与许可见 [第三方说明](../THIRD_PARTY.md)。以下门禁继续适用，完整写入安全与系统集成仍未验收：

- 固定上游提交并保存来源、许可证与构建选项。
- 确认只读打开、挂载与检查路径不会进行日志恢复、Dirty Flag 修改、休眠文件删除或其他隐式写入。
- 在设备 I/O 层强制拒绝写入，并在测试中记录所有写请求。
- 明确 FSKit 直接 I/O 与元数据缓存的使用策略，处理短读、短写与同步失败。
- 先完成只读本地卷，再启用经过验证的写入路径。

## M2 当前批次与下一步

已实现只读普通文件镜像的卷信息、目录分页、精确名称查找、文件内容与哈希输出。设备桥接在底层拒绝写模式和写回调；打开使用 READONLY/FORENSIC，整体健康与休眠状态不据读取成功推定。FSKit 使用 macOS 27 Handler，包含只读活动状态、item 生命周期、块对齐、目录与读接口，以及一律拒绝的修改接口。

宿主 app 与 `.appex` 可以由脚本构建；ad hoc 签名仅供工程核验。当前 `FSMediaTypes` 为空，没有注册扩展或接管 NTFS 插盘挂载。M2 原生退出条件仍全部待实机验证。

下一步先核对 macFUSE 已签名 FSKit 后端的目标系统行为、只读模式、本地卷属性和许可，再决定是否适合正式路线。仅在可丢弃介质上验证，不能用 KEXT、系统安全降级、网络共享或抢挂载守护进程弥补接入失败。若没有符合要求的接入与发布条件，应清楚报告产品阻碍；不会把付费账号申请留作默认用户任务。

已完成该后端的实际签名模块加载与只读镜像访问；存在磁盘工具设备身份、卷只读属性和正常推出缺口。原型与有限证据见 [macFUSE 实验](MACFUSE_EXPERIMENT.md)。下一步需先解决这些问题，再开放自动识别或写入；当前不能将本实验计为完整原生磁盘卷交付。

## 测试与证据

自动测试先使用合成引导头验证解析边界和拒绝路径；合成头不是完整 NTFS 卷，也不能替代引擎或挂载测试。随后使用 `mkntfs` 创建的可丢弃分区镜像进行只读和读写集成验证。

每次集成验收记录 macOS/SDK 版本、源码提交、扩展版本、引擎版本、卷特性、测试设备或镜像、挂载属性、文件哈希与退出结果。实机测试覆盖 Finder、磁盘工具、标准文件访问、重复插拔、重启、休眠和 Windows 交替使用。

所有破坏性测试仅在明确标记的专用测试盘或可丢弃镜像上执行。性能先建立同设备基准，再确定阈值。未完成的实机验收保持待验证状态。

## M1 验收记录

2026-10-12：在 macOS 27.0.1（26A434）/ arm64、Xcode 27.0（27A266a）、Swift 6.4 环境验证。

- Debug 编译与 14 项 XCTest 通过，覆盖结构与边界检查、Data 切片、特殊文件拒绝、镜像前后 SHA-256 一致性、CLI JSON 与退出码、FSKit 探测分类及稳定标识。
- Release 诊断程序与 FSKit 适配库编译通过，命令行帮助正常运行。复核入口为 `./scripts/check.sh`。
- Documents 内的 XCTest 产物曾因 Finder 元数据被签名工具拒绝；使用独立临时构建目录后通过，验证脚本采用相同方式。
- 本轮仅使用合成引导头与临时普通文件，不是完整 NTFS 卷；未对真实 FSKit 块设备执行 I/O，未安装或注册扩展。

M1 验证时 SIP 查询结果为 enabled；未核验启动安全策略，不能据此宣称 Full Security 集成已通过。

## M2 离线验收记录

同一目标环境中，75 个上游文件来源校验通过，25 项 XCTest 全部通过（M1 14 项与 M2 11 项），Release 引擎、两个 CLI、FSKit 模块入口和宿主 app 编译通过。测试来源与有限覆盖见 [测试说明](TESTING.md)。fixture 完整镜像与文件哈希一致；设备拒写回调和每次访问后的镜像不变性均有测试。独立审查指出的空闲簇数异常与祖先缓存缺失父身份已修复，并增加回归。

ad hoc 预览包签名完整性检查通过；最小启动实验被 AMFI 因 restricted entitlements 拒绝。官方 macFUSE 5.4.0 候选包已完成归档哈希、展开文件和模块签名／配置文件的只读检查，未执行其安装程序或注册组件。该材料核验不能替代实际 FSKit 加载。

尚未完成：FSKit 授权加载、Finder 本地卷、自动挂载、推出、重启恢复、Windows 往返、写入安全、故障恢复、性能及发布。M2 不能计为整体完成。
