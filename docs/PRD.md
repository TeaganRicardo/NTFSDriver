# macOS NTFS 原生读写支持工具

**产品需求文档（PRD v1.0）**

版本日期：2026-10-12

目标平台：macOS 27 / Apple Silicon

项目性质：原生系统工具/驱动

## 一、项目背景与目标

### 1.1 项目背景

macOS 原生支持读取 NTFS 文件系统，但默认不提供可靠的 NTFS 写入支持。

现有解决方案存在不同程度的局限：

- Paragon NTFS、Tuxera NTFS 等商业驱动需要付费，部分方案依赖内核扩展，并要求降低 Apple Silicon Mac 的启动安全等级。
- NTFS-3G 配合 FUSE-T 可以实现 NTFS 读写，但文件系统挂载、Finder 集成和自动化体验不够理想。
- macFUSE 等通用文件系统框架增加了额外依赖，部分运行模式需要内核扩展。
- 新兴 FSKit 方案具备更好的系统集成潜力，但其成熟度、兼容性和可靠性仍有待验证。

Apple 已提供 FSKit，允许第三方文件系统通过用户空间扩展接入 macOS 的文件系统管理机制。

### 1.2 核心目标

开发一款**高度原生化、无需日常维护、能够透明支持 NTFS 读写的 macOS 工具**。

理想状态下，用户完成一次安装与必要的系统授权后，就不再需要主动感知该工具的存在。

插入 NTFS 移动硬盘后，系统应像处理 exFAT 或 APFS 磁盘一样，自动完成识别、挂载和文件访问。

### 1.3 产品原则

1. **原生集成优先**：尽可能使用 Apple 公开提供的系统接口。
2. **无感运行**：不增加不必要的启动、操作和管理流程。
3. **数据安全优先**：任何不确定情况下优先保护文件系统完整性。
4. **保持系统安全性**：不要求关闭 SIP、降低启动安全等级或安装第三方 KEXT。
5. **最小化产品复杂度**：只提供必要的管理和诊断能力。
6. **免费与开源**：不设置订阅、授权验证或功能付费限制。

## 二、目标用户体验

### 2.1 首次安装

用户下载安装包后，完成一次安装。

安装过程应：

- 自动部署所需文件系统组件。
- 引导完成 macOS 必需的系统授权。
- 清晰报告扩展是否成功注册并启用。
- 检查与其他 NTFS 驱动之间的潜在冲突。
- 在安装完成后自动进入正常工作状态。

除 macOS 强制要求的授权外，不应要求用户执行额外的终端命令。

如果由于开发者签名、系统权限或兼容性问题而无法完成安装，应准确告知原因。

### 2.2 日常使用

正常情况下，用户无需打开工具。

插入 NTFS 设备后：

1. macOS 自动识别文件系统。
2. 正常状态的 NTFS 分区自动以读写模式挂载。
3. Finder 侧边栏出现对应磁盘。
4. 用户可以直接打开、复制、编辑或删除文件。
5. 其他 macOS 应用能够通过标准文件访问接口操作磁盘。
6. 用户可以通过 Finder 或磁盘工具正常推出设备。

磁盘应挂载在系统标准的 `/Volumes` 路径下。

**重要要求：NTFS 磁盘应被 macOS 识别为正常的本地磁盘卷，而非模拟网络共享、SMB/NFS 服务器或需要手动访问的普通目录。**

这也是此前 FUSE-T + NTFS-3G 方案未满足的核心体验要求。

### 2.3 用户界面

不需要传统意义上的主界面。

允许提供一个极简的设置或诊断程序，但它不应成为日常使用的必要条件。

正常运行期间：

- 不需要常驻菜单栏图标。
- 不需要显示 Dock 图标。
- 不需要手动点击挂载或卸载按钮。
- 不需要用户指定挂载路径。
- 不需要在每次插入磁盘时重复授权。
- 不需要显示无实际意义的状态通知。

当用户主动打开管理程序时，可以查看已安装版本、文件系统扩展状态、已连接 NTFS 卷，以及必要的诊断信息。

只有需要用户采取行动的异常才应主动提示。

## 三、功能需求

### 3.1 P0：核心功能

| ID | 功能 | 需求 |
| --- | --- | --- |
| P0-01 | NTFS 识别 | 自动识别连接到 Mac 的 NTFS 分区 |
| P0-02 | 自动挂载 | 无需手动操作即可挂载正常 NTFS 卷 |
| P0-03 | 完整读写 | 支持常规文件和目录的读取、创建、修改、删除 |
| P0-04 | 本地磁盘集成 | Finder、磁盘工具及系统文件访问 API 能正常识别 |
| P0-05 | 标准挂载位置 | 按 macOS 约定挂载至 `/Volumes` |
| P0-06 | 安全推出 | 支持正常卸载、刷新待写入数据与安全推出 |
| P0-07 | 自动恢复 | 重启系统后仍能自动识别和挂载 NTFS 设备 |
| P0-08 | 系统安全 | 保持 SIP、Full Security，不使用第三方内核扩展 |
| P0-09 | 多卷支持 | 多个 NTFS 分区可以同时独立挂载 |
| P0-10 | 安全降级 | 存在文件系统风险时拒绝写入，必要时只读挂载 |
| P0-11 | 冲突处理 | 避免与 macOS 自带 NTFS 驱动争夺挂载造成异常 |

其中，P0-04 是最重要的验收项之一。

仅证明某个目录能够读取 NTFS 文件，并不代表完成了产品目标。

### 3.2 P1：完整日常使用体验

| ID | 功能 | 需求 |
| --- | --- | --- |
| P1-01 | Finder 元数据 | 正确支持扩展属性、文件标签及必要的 macOS 元数据 |
| P1-02 | 文件信息 | 正确读取和保存文件大小、创建时间、修改时间等信息 |
| P1-03 | 文件命名 | 支持 Unicode、中文名称、长文件名及 NTFS 大小写语义 |
| P1-04 | 文件操作兼容性 | 支持常见应用的保存、覆盖、临时文件替换及原子重命名操作 |
| P1-05 | 并发访问 | 支持多个进程同时访问同一磁盘 |
| P1-06 | 文件生命周期 | 正确处理文件仍被打开时的重命名、替换、删除 |
| P1-07 | 休眠唤醒 | macOS 休眠及恢复后保持合理的卷状态 |
| P1-08 | 热插拔处理 | 妥善处理非正常拔盘及设备突然断开 |
| P1-09 | Windows 兼容 | macOS 写入的数据可以被 Windows 正确读取和修改 |
| P1-10 | 异常诊断 | 提供可理解的错误信息及必要的诊断日志 |
| P1-11 | 完整卸载 | 可以干净卸载文件系统扩展及相关组件 |
| P1-12 | 升级兼容 | 应用更新不会破坏现有磁盘挂载配置及数据 |

对于 Finder 元数据，必须特别关注 NTFS Alternate Data Streams、扩展属性以及 AppleDouble 文件之间的兼容性。

不得在未确认数据安全的情况下，自动清理既有的 `._` 文件或迁移元数据。

## 四、可靠性与数据安全

这是项目最重要的非功能性需求。

### 4.1 文件系统完整性

工具应遵循以下原则：

- 不得对无法可靠识别的分区执行写入。
- 不得静默执行存在数据损坏风险的操作。
- 不得擅自清除 NTFS Dirty Flag。
- 不得擅自修改 Windows 休眠状态。
- 不得在文件系统状态不明确时强制读写挂载。
- 不得自行执行可能造成数据损失的自动修复。

对于 Windows 快速启动、休眠或未正常卸载的 NTFS 分区，应按实际风险拒绝读写，必要时提供只读访问。

遇到需要修复的情况，可以提示用户通过 Windows `chkdsk` 等适当工具处理。

### 4.2 异常处理

需要覆盖以下情况：

1. 文件正在写入时发生设备断开。
2. 文件系统操作进行中，驱动扩展意外退出。
3. 计算机进入睡眠或突然关机。
4. 磁盘出现 I/O 错误。
5. 磁盘空间耗尽。
6. 外置磁盘连接不稳定。
7. 用户同时进行大量文件操作。
8. 磁盘包含损坏、不完整或不常见的 NTFS 元数据。

这些情况下，驱动应尽可能保持文件系统状态一致，并准确向上层应用返回错误。

### 4.3 数据安全验证

必须具备可重复执行的数据完整性测试。

至少覆盖：

- 大文件连续读写。
- 大量小文件创建与删除。
- 深层目录操作。
- 文件覆盖与重命名。
- 并发读写。
- 反复挂载和卸载。
- 长时间持续读写。
- Windows 与 macOS 交替使用。
- 不正常断开设备后的恢复行为。

通过哈希或等效方式验证测试数据的一致性。

**所有破坏性测试必须使用专用测试磁盘或可丢弃的磁盘镜像，不得直接在用户的生产数据盘上执行。**

## 五、性能要求

性能优化应以可靠性为前提。

### 5.1 基本目标

在设备本身不是性能瓶颈的情况下：

- 常规文件复制速度不应出现不合理的数量级下降。
- 不应因频繁文件访问导致 Finder 长时间无响应。
- 长时间运行不应出现持续性的内存泄漏。
- 多任务文件访问不应造成系统级卡死。
- 空闲状态的 CPU 和内存占用应保持较低水平。

### 5.2 性能验收

需要建立统一的性能测试基准，包括：

| 测试项目 | 内容 |
| --- | --- |
| 顺序读取 | 大文件持续读取 |
| 顺序写入 | 大文件持续写入 |
| 随机读写 | 小块随机 I/O |
| 小文件操作 | 大量小文件创建、复制及删除 |
| 目录遍历 | 包含大量条目的目录 |
| 并发性能 | 多进程访问 |
| 长期运行 | 连续读写及反复挂载 |

测试结果应与同一设备在 Windows 原生 NTFS 环境下的表现进行比较，并在适用情况下与其他 macOS 驱动对比。

第一阶段不预设脱离实际设备条件的固定吞吐量指标。完成基准测试后，再确定具体性能验收阈值。

## 六、技术与系统约束

本项目不预先指定详细实现架构，但存在以下明确约束。

### 6.1 系统兼容性

首要目标：

- Apple Silicon。
- macOS 27。
- macOS 27.0.1 作为初始开发与验证环境。

其他 macOS 版本可以后续扩展。

### 6.2 系统接口

优先使用 Apple 官方提供的 FSKit 等公开接口。

尽可能避免以下方式作为正式产品的最终实现：

- 修改 macOS 系统文件来启用隐藏的 NTFS 写入功能。
- 依赖第三方 KEXT。
- 要求关闭 SIP。
- 要求降低启动安全等级。
- 将 NTFS 磁盘伪装为 SMB/NFS 网络共享。
- 要求用户长期执行手动挂载命令。

不要求重新实现 NTFS 文件系统引擎，可以评估并复用已有的成熟开源组件。
